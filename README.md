# autoeffort

Мод для Claude Code, що задає effort кожного запиту до моделі за фазою роботи: збір контексту, планування, реалізація, перевірка. Effort встановлюється для кожного кроку моделі (`turn.step`) окремо, в основному треді й у кожному субагенті.

## Фази і рівні

| Фаза | Маркер | Рівень за замовчуванням |
|---|---|---|
| збір контексту | `⟦phase:gather⟧` | `medium` |
| аналіз і планування | `⟦phase:plan⟧` | `xhigh` |
| реалізація | `⟦phase:implement⟧` | `medium` |
| перевірка | `⟦phase:verify⟧` | `xhigh` |

Використовуються лише `medium`, `high`, `xhigh`, `max`. Рівень `low` не використовується: вхідний чи обчислений `low` піднімається до `medium` (підлога `medium`).

## Як визначається фаза

1. **Маркер.** Мод додає до системного промпту секцію `autoeffort:phase-marker`: на початку кожної відповіді модель оголошує одним маркером, чим займатиметься в наступному кроці (`⟦phase:gather|plan|implement|verify⟧`, символи U+27E6 / U+27E7). Маркер вирізається з потоку відповіді, навіть розірваний між шматками, тож його не видно ні на екрані, ні в історії. Маркер, що потрапив у thinking, теж не показується, але фазу задає лише маркер у тексті відповіді. Він діє на один наступний крок свого треду.
2. **Правила**, якщо маркера не було:
   - перший крок ходу → `plan`;
   - кілька кроків поспіль лише з читаннями (поріг `readStreak`, типово 3) → `plan`;
   - лише Read, Grep, Glob, LS, WebFetch, WebSearch → `gather`;
   - Edit, MultiEdit, Write, NotebookEdit → `implement`;
   - Bash із командою перевірки (`verifyPattern`) після редагування в ході → `verify`;
   - інакше — фаза попереднього кроку треду, а без неї `plan`.

## Межа скіла чи агента

Базовий рівень сесії — `effort`, з яким прийшов крок основного треду поза скілом. Якщо скіл (наприклад, з `effort: max` у frontmatter) або субагент приходить з іншим рівнем, цей рівень стає нижньою межею: підсумок = max(рівень фази, межа). Межа скіла знімається наприкінці ходу основного треду.

## Налаштування

Параметри `userConfig` (змінюються через `/config` або в `~/.claude/settings.json`). Ключ у `pluginConfigs` — `autoeffort@autoeffort` для встановленого мода і `autoeffort` для підключеного з локальної теки:

```json
{
  "pluginConfigs": {
    "autoeffort@autoeffort": {
      "options": {
        "enabled": true,
        "gather": "medium",
        "plan": "xhigh",
        "implement": "medium",
        "verify": "xhigh",
        "readStreak": 3,
        "verifyPattern": "(^|[\\s;&|(])((npm|pnpm|yarn|bun)\\s+(run\\s+)?(test|lint|build|typecheck|check)(?![\\w-])|npx\\s+(jest|vitest|eslint|tsc)\\b|(jest|vitest|pytest|eslint|tsc|mypy|ruff)(\\s|$)|cargo\\s+(check|test|clippy)\\b|go\\s+(test|vet)\\b|make\\s+(test|check|lint)\\b)"
      }
    }
  }
}
```

## Встановлення

У рядку вводу Claude Code в терміналі:

```
/plugin install autoeffort --marketplace dmytro-rudenko/autoeffort
```

Далі `y`, щоб додати маркетплейс, вибір області встановлення і екран із параметрами. Мод починає працювати в цій самій сесії, без перезапуску.

### З локальної теки

Для розробки мод підключається з клону репозиторію, разово:

```sh
git clone https://github.com/dmytro-rudenko/autoeffort.git ~/autoeffort
claude --plugin-dir ~/autoeffort
```

Постійно — через `CLAUDE_CODE_PLUGIN_DIRS` у `env` файлу `~/.claude/settings.json`:

```json
{ "env": { "CLAUDE_CODE_PLUGIN_DIRS": "~/autoeffort" } }
```

## Команда `/autoeffort`

- `/autoeffort` — стан: увімкнено чи ні, базовий рівень (`baseline`), активний скіл, фаза кожного треду і останні 20 рішень у вигляді `<тред>#<крок> <рівень> · <фаза> (<джерело>)`, з межею — суфікс ` ↑<мітка>:<рівень>`, наприклад `↑skill:review:max` чи `↑agent:max`.
- `/autoeffort on` / `/autoeffort off` — увімкнути чи вимкнути без перезапуску. Вимкнений мод нічого не переписує і не додає секцію промпту.
- `/autoeffort log` — повний лог рішень сесії: час (ISO), тред, крок, рівень, фаза, джерело, межа і вхідний effort.

Після кожного рішення основного треду статус-рядок показує `⚙ <рівень> · <фаза> (<джерело>)`, наприклад `⚙ high · gather (rule:read) ↑skill`: тут межа скорочена до `↑skill` чи `↑agent`, без назви скіла й рівня. Крок основного треду без `effort` і `/autoeffort off` очищають статус-рядок.

## Відомі обмеження

1. Якщо перший хід сесії — скіл із власним effort, базового рівня ще немає, тож його межа не розпізнається.
2. Прапорець скіла спільний для всієї сесії: скіл, підвантажений у субагенті, позначає рішення основного треду в лозі як обмежені межею скіла.
3. Зміна `enabled` у `/config` після гарячого перезавантаження діє з наступної сесії; щоб перемкнути одразу, використовуйте `/autoeffort on|off`.
4. Правила дивляться на минулі кроки, тож на межі фаз один крок може отримати неточний рівень. Маркер це зменшує, але не усуває.
5. Effort задається на запит до моделі, а не на окремий інструмент.
6. Якщо рушій повідомляє effort числом (бюджет токенів), а не рівнем, мод не може розпізнати межу скіла чи агента і замінює число рівнем фази.

Якщо в моделі немає `effort` або в логіці мода сталася помилка, запит іде без змін (fail-open), а помилка пишеться в лог.
